# AGENTS.md — правила для ИИ-ассистентов в репозитории doxdix

## Что это за проект

`doxdix` — локальный CLI для генерации и актуализации документации проекта
через локальную LLM (Ollama). Пофайловый обход кода, сохранение ручных
разделов документации, бэкапы перед изменениями.

Полное ТЗ — в задании, по которому ведётся разработка (см. историю проекта).

## Технологии

- Python >= 3.10
- Единственная внешняя зависимость: `requests>=2.31`
- HTTP API Ollama (`/api/chat`, `/api/tags`)
- Установка: `pipx install git+https://github.com/<user>/doxdix.git`
- Обновление: `pipx install --force git+https://github.com/<user>/doxdix.git`
- Удаление: `pipx uninstall doxdix`

## Конвенции кода

### Версионирование файлов
Каждый Python-файл содержит:
```python
dv_file_version = 'YYMMDD.NN'
```
При изменении файла — обновлять версию. Формат: `год_месяц_день.NN`.
Пример: `261028.01` (28 октября 2026, первая правка за день).

### Логирование
Только стандартный `logging`. Никаких `print()` в библиотечном коде.
`cli.py` настраивает хендлеры (stdout + файл), остальные модули используют
`logger = logging.getLogger(__name__)`.

### Зависимости
Не добавлять новых зависимостей без крайней необходимости. `requests` —
единственная внешняя зависимость.

### Стиль
- Type hints — где это не усложняет код.
- Докстринги — короткие, по делу.
- Не рефакторить код, если задача этого не требует.

### Архитектура
Раскладка модулей фиксирована:
- `cli.py` — argparse, `main()`, проверка Ollama, диспетчеризация.
- `scanner.py` — обход файлов, исключения, git-данные.
- `changelog_gen.py` — парсер Conventional Commits + генератор CHANGELOG.md.
- `backup.py` — создание/восстановление/ротация бэкапов.
- `prompts.py` — шаблоны промптов.
- `llm.py` — HTTP-клиент Ollama + `LLMError`.
- `orchestrator.py` — конвейер шагов 0–5, логирование, коммиты.

## Правила для ИИ

1. Не менять архитектуру (раскладку модулей) без явного указания.
2. Не добавлять конфиг-файлы — все параметры через CLI.
3. Перед правками уточнять, если задача неоднозначна.
4. Обновлять `dv_file_version` в каждом изменённом файле.
5. Проверять синтаксис: `python -m py_compile src/doxdix/*.py`.
6. Документация — в `README.md`, история — в `CHANGELOG.md`.
7. Не трогать `LICENSE` целевого проекта (doxdix его только читает).
8. `requests` — единственная зависимость, не тянуть лишнего.

## Карта: что изменил → что обновить

| Что изменил | Что обновить |
|---|---|
| `cli.py` (флаги) | `README.md` (раздел «Использование»), `--help` |
| `orchestrator.py` (шаги конвейера) | `README.md` (раздел «Как работает») |
| `llm.py` (протокол Ollama) | `README.md` (раздел «Требования») |
| `scanner.py` (исключения/фильтры) | `README.md` (раздел «Исключения») |
| `backup.py` (формат бэкапов) | `README.md` (раздел «Бэкапы») |
| Новый модуль | `README.md` + этот `AGENTS.md` |
| Существенное изменение (feat/fix/refactor) | `CHANGELOG.md` |

## Когда обновлять CHANGELOG.md

**Обновлять, если:**
- Добавлена новая фича (feat).
- Исправлен баг (fix).
- Изменена архитектура (refactor, BREAKING CHANGE).
- Изменён публичный API (флаги CLI, формат бэкапов, формат CHANGELOG).

**НЕ обновлять, если:**
- Мелкая правка форматирования.
- Обновление комментариев без изменения логики.
- Правки только в документации.

**Формат записи:** Keep a Changelog, секция `[Unreleased]`, подсекции
`Added` / `Fixed` / `Changed` / `Documentation` / `Breaking Changes` /
`Other`.

## Принципы документации

1. Документация — рядом с кодом. README лежит в корне.
2. Один файл — одна тема.
3. Не дублировать код. Ссылаться на файл и функцию.
4. Актуальность важнее полноты.
5. История — в `CHANGELOG.md`, не в README.

## Анти-паттерны

**НЕ делать:**
- Копировать код в README.
- Описывать то, чего ещё нет (планы ≠ документация).
- Обновлять все файлы подряд «на всякий случай».
- Оставлять устаревшие разделы «на память».
- Создавать новые файлы документации без обновления корневого README.

## Когда обновлять AGENTS.md

Обновлять только если:
- Изменилась структура проекта (появились/удалились модули).
- Изменились конвенции кода.
- Изменились общие правила для ИИ.
- Появились/удалились ключевые файлы.

НЕ обновлять при мелких правках в отдельных модулях.
