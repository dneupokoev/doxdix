# Модуль сканирования проекта

## Назначение
Модуль сканирует целевой проект и возвращает список файлов для дальнейшей обработки вместе с git-данными. Если git доступен и в проекте есть репозиторий, используются только отслеживаемые файлы (`git ls-files`), отфильтрованные по расширениям и исключениям. Если git недоступен, отключён или не дал отслеживаемых файлов, выполняется рекурсивный обход файловой системы с теми же фильтрами.

Версия модуля: `dv_file_version = '261028.02'`.

## Публичный API

### `scan(project_root, src_dir, extensions, user_excludes, use_git, changelog_limit) -> tuple[list[Path], GitData]`
Сканирует проект и возвращает `(files, git_data)`.

Аргументы:
- `project_root` — корень целевого проекта (`Path`).
- `src_dir` — относительный путь подпапки с кодом либо `None` для всего проекта.
- `extensions` — список расширений, например `['.py', '.ts']`.
- `user_excludes` — список имён папок/паттернов исключений из `--exclude`.
- `use_git` — `False`, если передан `--no-git`.
- `changelog_limit` — сколько последних коммитов брать для CHANGELOG.

Возвращает:
- список абсолютных `Path`, отсортированный по строковому пути;
- `GitData` с информацией о наличии git, коммитах и отслеживаемых файлах.

Исключения:
- `ValueError`, если `project_root` не является директорией;
- `ValueError`, если `src_dir` задан, но не найден или не является директорией.

## Классы данных
- `GitCommit` — один коммит из git log: `sha`, `subject`, `body`. Класс `frozen=True`.
- `GitData` — результат сбора git-данных: `has_git`, `commits`, `tracked_files`.

## Основные внутренние функции
- `_matches_glob(name, pattern) -> bool` — сопоставляет имя файла glob-паттерну через `fnmatch`.
- `_is_excluded(rel_path, user_excludes) -> bool` — проверяет путь на исключения по папкам и имени файла.
- `_normalize_extensions(extensions) -> tuple[str, ...]` — приводит расширения к нижнему регистру, добавляет ведущую точку и отбрасывает пустые значения.
- `_run_git(project_root, args, timeout=30) -> str | None` — запускает git-команду через `subprocess.run`, логирует ошибки как warning и возвращает stdout либо `None`.
- `_get_git_commits(project_root, limit) -> list[GitCommit]` — получает последние коммиты без merge в формате `%H|%s|%b`.
- `_get_tracked_files(project_root) -> set[str]` — получает относительные пути отслеживаемых файлов через `git ls-files`.
- `_collect_git_data(project_root, use_git, changelog_limit) -> GitData` — собирает git-данные, если git разрешён и репозиторий существует.
- `_iter_filesystem(scan_root, project_root, extensions, user_excludes) -> list[Path]` — рекурсивно обходит файловую систему, если git-фильтрация недоступна.
- `_iter_tracked(git_data, project_root, scan_prefix, extensions, user_excludes) -> list[Path]` — фильтрует отслеживаемые git-файлы по префиксу, расширениям и исключениям.
- `_count_untracked(scan_root, project_root, extensions, user_excludes, git_data) -> int` — информативно считает файлы на диске, не отслеживаемые git.

## Правила сканирования
- При доступном git обрабатываются только отслеживаемые файлы.
- При недоступном git, `use_git=False`, отсутствии `.git` или пустом `git ls-files` выполняется обход файловой системы.
- Если список расширений после нормализации пуст, возвращается `([], GitData(has_git=False))` с warning.
- Исключения по умолчанию для папок: `.git`, `.doxdix`, `node_modules`, `__pycache__`, `venv`, `.venv`, `env`, `dist`, `build`, `tests`, `test`, `.mypy_cache`, `.pytest_cache`, `.ruff_cache`, `target`.
- Исключения по умолчанию для файлов: `test_*`, `*_test.*`, `*.min.*`, `*.spec.*`, `conftest.py`.
- Пользовательские исключения применяются к именам папок в пути и к имени файла через `fnmatch`.
- Расширения нормализуются: приводятся к нижнему регистру и получают ведущую точку.
- `src_dir` задаёт подпапку сканирования и относительный префикс для `git ls-files`; `project_root` и `src_dir` приводятся к абсолютным путям.
- Ошибки отдельных git-команд логируются как warning. Если не удалось получить список отслеживаемых файлов, модуль переходит на обход файловой системы; если не удалось получить только git log, сканирование может продолжиться с пустым списком коммитов.
- Git-команды выполняются с таймаутом 30 секунд по умолчанию.
- Результат сканирования сортируется по строковому представлению пути.

## Зависимости
Модуль использует только стандартную библиотеку Python:
- `__future__.annotations`;
- `logging`;
- `subprocess`;
- `dataclasses.dataclass`, `dataclasses.field`;
- `pathlib.Path`;
- локально `fnmatch.fnmatch`;
- локально `re`.

Импортов из других модулей проекта в файле нет.

## Использование другими модулями проекта
По изолированному файлу прямые импорты и вызовы из других модулей не видны. Публичная точка входа модуля — `scan(...)`; предполагаемое использование другими модулями: вызвать `scan(...)` и использовать возвращённые `files` и `GitData`. `GitData` и `GitCommit` являются частью публичного результата и могут использоваться вызывающим кодом для доступа к git-информации.

## Ограничения и заметки
- Пути из `git ls-files` считаются относительными от корня проекта и ожидаются в POSIX-формате.
- Отслеживаемые файлы, отсутствующие на диске, пропускаются с debug-логом.
- `_count_untracked` используется только для информационного лога и не влияет на результат сканирования.
- Парсер `_get_git_commits` рассчитан на формат `%H|%s|%b` и SHA длиной 40 hex-символов.
- Записи коммитов выделяются по строкам, начинающимся с 40-символьного SHA; строки продолжения многострочного body не собираются в `body` надёжным образом.
- Пользовательские исключения проверяются по отдельным компонентам пути и имени файла, а не по полному относительному пути.
- Результат сканирования сортируется по строковому представлению пути.
