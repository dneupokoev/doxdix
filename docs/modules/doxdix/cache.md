# Кэш SHA-256 исходного кода

## Назначение

Модуль хранит SHA-256 хэши исходных файлов в `<project>/.doxdix/cache.json`. Кэш позволяет не отправлять в LLM файлы, код которых не менялся с прошлого запуска, экономя токены и время.

Формат файла: JSON-объект вида `{"относительный/путь.py": "<sha256 в hex>"}`.

## Расположение и константы

- `CACHE_DIR = ".doxdix"` — каталог кэша в корне проекта.
- `CACHE_FILENAME = "cache.json"` — имя файла кэша.
- `dv_file_version = "261028.18"` — версия модуля.
- `cache_file_path(project_root: Path) -> Path` — возвращает путь `<project_root>/.doxdix/cache.json`.

## Публичный API

### `file_sha256(code_path: Path) -> str | None`

Считает SHA-256 содержимого файла и возвращает hex-строку. Файл читается порциями по 1 МБ. При `OSError` пишет предупреждение в лог и возвращает `None`.

### `class Cache`

Кэш хэшей файлов, загруженный из `.doxdix/cache.json`.

- `Cache(project_root: Path, data: dict[str, str] | None = None)` — создаёт объект кэша; `data` задаёт начальные записи.
- `Cache.load(project_root: Path) -> Cache` — читает кэш из файла. Если файл отсутствует, повреждён, не является JSON-объектом или не читается, возвращает пустой кэш и логирует предупреждение.
- `get(rel_key: str) -> str | None` — возвращает хэш по относительному ключу пути или `None`.
- `set(rel_key: str, sha: str) -> None` — сохраняет хэш в памяти; запись на диск произойдёт при `save()`. Помечает кэш изменённым только если значение отличается.
- `is_unchanged(rel_key: str, sha: str, md_path: Path) -> bool` — возвращает `True`, если хэш совпадает с кэшем и итоговый `.md` уже существует.
- `save() -> bool` — записывает кэш на диск, если были изменения. Создаёт родительский каталог, пишет JSON с `ensure_ascii=False`, `indent=2`, `sort_keys=True` и завершающим переводом строки. При `OSError` логирует предупреждение и возвращает `False`; при успехе или отсутствии изменений возвращает `True`.

## Поведение и ограничения

- Отсутствующий или битый файл кэша не является фатальной ошибкой: кэш считается пустым.
- При загрузке все ключи и значения приводятся к строкам; дополнительная валидация хэшей не выполняется.
- `is_unchanged` учитывает не только хэш, но и наличие итогового `.md`-файла.
- `save()` не перезаписывает файл, если не было изменений.
- Флаг `RunConfig.force`, упомянутый в docstring, в этом модуле не реализован; по описанию он обрабатывается выше, в `cli.py`, и заставляет игнорировать кэш.
- В модуле нет явной синхронизации/блокировок для конкурентного доступа к файлу кэша.

## Зависимости

Используются только стандартная библиотека и `pathlib`:

- `hashlib` — расчёт SHA-256.
- `json` — чтение и запись JSON.
- `logging` — предупреждения и отладочные сообщения.
- `pathlib.Path` — работа с путями.
- `from __future__ import annotations` — отложенная оценка аннотаций.

Импортов других модулей проекта в этом файле нет.

## Использование в проекте

В изолированном файле нет импортов других модулей проекта, поэтому конкретные места вызова не видны. По docstring модуль предназначен для CLI/оркестратора: перед обработкой файла можно вычислить `file_sha256(...)`, проверить `Cache.is_unchanged(...)` и пропустить неизменённые файлы; после обработки — обновить кэш через `Cache.set(...)` и `Cache.save()`. При включённом `--force` кэш должен игнорироваться вызывающим кодом.
