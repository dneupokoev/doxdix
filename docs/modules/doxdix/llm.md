# llm_client.py

## Назначение

HTTP-клиент для работы с LLM. Поддерживает два режима, которые определяются по `base_url`:

- **Ollama** (`/api/*`) — POST `/api/chat`, GET `/api/tags`, без авторизации.
- **OpenAI-совместимый** (`/v1/*`) — POST `/chat/completions`, GET `/models`, заголовок `Authorization: Bearer <api_key>`.

Режим считается OpenAI-совместимым, если `base_url` (без завершающего `/`) оканчивается на `/v1` или содержит `/v1/`. Иначе — Ollama.

Версия файла: `261028.11`.

## Публичный API

### `class LLMError(Exception)`

Единая ошибка клиента. Атрибуты:

- `message: str` — текст ошибки.
- `status: int | None` — HTTP-код (если применимо).
- `body: str | None` — тело ответа (обрезается до 1000 символов).

Бросается при любых проблемах: сетевые ошибки, таймаут, HTTP != 200, не-JSON ответ, отсутствие/пустой `content`.

### `chat(base_url, model, prompt, num_ctx, timeout, api_key="dummy") -> str`

Отправляет один пользовательский промпт в LLM и возвращает `content.strip()`.

Аргументы:
- `base_url` — базовый URL сервера (определяет режим).
- `model` — имя модели.
- `prompt` — текст запроса.
- `num_ctx` — размер контекста. Используется **только в режиме Ollama** (передаётся в `options.num_ctx`); в OpenAI-режиме игнорируется.
- `timeout` — таймаут запроса, секунды.
- `api_key` — ключ для OpenAI-режима (по умолчанию `"dummy"`). Пустая строка → запрос без `Authorization`.

Особенности:
- В Ollama-режиме при `len(prompt)//4 > num_ctx` пишется предупреждение в лог (запрос не блокируется).
- Запросы выполняются с `stream=False`.
- Любая ошибка → `LLMError`.

### `check_model(base_url, model, timeout=10, api_key="dummy") -> list[str]`

Проверяет доступность сервера и возвращает список имён моделей.

- Ollama: разбирает `data["models"][].name`.
- OpenAI: разбирает `data["data"][].id`. При HTTP 404 на `/models` — предупреждение в лог и возврат пустого списка (некоторые прокси не реализуют эндпоинт, но чат может работать).

Наличие конкретной `model` в списке проверяет вызывающая сторона (см. `cli.py`) — сама функция этого не делает. При недоступности сервера бросает `LLMError`.

## Внутренние функции

- `_is_openai_mode(base_url)` — определение режима по URL.
- `_ollama_chat_url`, `_ollama_tags_url`, `_openai_chat_url`, `_openai_models_url` — построение URL.
- `_auth_headers(api_key)` — заголовок `Authorization`, если ключ непустой.
- `_chat_ollama(...)`, `_check_ollama(...)` — реализация Ollama-режима.
- `_chat_openai(...)`, `_check_openai(...)` — реализация OpenAI-режима.

## Зависимости

- `logging` — логирование предупреждений (`num_ctx`, 404 на `/models`).
- `requests` — HTTP-запросы (`POST`, `GET`), обработка `Timeout` и `RequestException`.
- `from __future__ import annotations` — отложенная аннотация типов.

## Использование в проекте

Модуль выступает низкоуровневым слоем доступа к LLM и вызывается из других модулей проекта:

- `cli.py` вызывает `check_model(...)` при проверке доступности сервера и получении списка моделей для отображения пользователю; сопоставление имени модели выполняет сам `cli.py`.
- Предполагаемый вызов `chat(...)` — для отправки промптов в LLM в основном рабочем потоке.

Обе функции пробрасывают `LLMError`, перехват и пользовательское сообщение формируются на стороне вызывающего кода.

## Примечания и ограничения

- Публичный контракт: HTTP != 200, отсутствие `choices[0].message.content` (OpenAI) или `message.content` (Ollama), пустой `content` → `LLMError`.
- Тело ответа в `LLMError.body` обрезается до 1000 символов.
- В OpenAI-режиме `num_ctx` не передаётся — размер контекста определяет сервер.
- Авторизация поддерживается только в OpenAI-режиме; Ollama-эндпоинты вызываются без заголовков авторизации.
- Для OpenAI-совместимых прокси без `/v1/models` проверка имён моделей возвращает `[]` и сопровождается предупреждением.
