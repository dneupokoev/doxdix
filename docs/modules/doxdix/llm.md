# llm_client.py

## Назначение

HTTP-клиент для работы с LLM. Поддерживает два режима, определяемые по `base_url`:

- **Ollama** (`/api/*`) — `POST /api/chat`, `GET /api/tags`, без авторизации.
- **OpenAI-совместимый** (`/v1/*`) — `POST /chat/completions`, `GET /models`, заголовок `Authorization: Bearer <api_key>` при непустом ключе.

Режим считается OpenAI-совместимым, если `base_url` после удаления завершающего `/` оканчивается на `/v1` или содержит `/v1/`. Иначе используется режим Ollama.

Версия файла: `261028.12`.

Публичный API: `LLMError`, `chat(...)`, `check_model(...)`.

## Публичный API

### `class LLMError(Exception)`

Единая ошибка клиента: `LLMError(message, status=None, body=None)`.

Атрибуты:

- `message: str` — текст ошибки.
- `status: int | None` — HTTP-код, если применимо.
- `body: str | None` — тело ответа, обрезается до 1000 символов.

В `chat(...)` бросается при сетевых ошибках, таймаутах, `HTTP != 200`, не-JSON ответе, отсутствии или пустом `content`. В `check_model(...)` есть отдельные исключения для OpenAI-режима: HTTP 404 на `/models` и пустой список моделей при HTTP 200 не считаются ошибкой.

### `chat(base_url, model, prompt, num_ctx, timeout, api_key="dummy") -> str`

Отправляет один пользовательский промпт в LLM и возвращает `content.strip()`.

Аргументы:

- `base_url` — базовый URL сервера, определяет режим работы.
- `model` — имя модели.
- `prompt` — текст запроса.
- `num_ctx` — размер контекста. Используется только в режиме Ollama, передаётся в `options.num_ctx`; в OpenAI-режиме игнорируется.
- `timeout` — таймаут запроса в секундах.
- `api_key` — ключ для OpenAI-режима, по умолчанию `"dummy"`. Пустая строка означает запрос без `Authorization`.

Особенности:

- В Ollama-режиме при `len(prompt)//4 > num_ctx` пишется предупреждение в лог, запрос не блокируется.
- В OpenAI-режиме `num_ctx` не передаётся — размер контекста определяет сервер.
- Запросы выполняются с `stream=False`.
- В OpenAI-режиме для chat отправляется `Content-Type: application/json`; `Authorization` добавляется только при непустом `api_key`.
- Любая ошибка запроса или ответа приводит к `LLMError`.

### `check_model(base_url, model, timeout=10, api_key="dummy") -> list[str]`

Проверяет доступность сервера и возвращает список имён моделей.

Аргументы:

- `base_url` — базовый URL сервера, определяет режим работы.
- `model` — имя проверяемой модели; внутри функции не используется, наличие модели в списке проверяет вызывающая сторона, например `cli.py`.
- `timeout` — таймаут запроса в секундах, по умолчанию `10`.
- `api_key` — ключ для OpenAI-режима, по умолчанию `"dummy"`. Пустая строка означает запрос без `Authorization`.

Поведение:

- Ollama: `GET /api/tags`, разбирает `data["models"][].name`. Пустой `/api/tags` или отсутствие валидных имён — `LLMError`, так как запрошенной модели точно нет; пользователю нужно выполнить `ollama pull`.
- OpenAI: `GET /models`, разбирает `data["data"][].id`. При HTTP 404 на `/models` пишется предупреждение в лог и возвращается `[]`: некоторые прокси не реализуют эндпоинт, но чат может работать. Пустой список также возможен при HTTP 200, если в ответе нет валидных элементов `data[].id`; это не ошибка.
- При недоступности сервера, иных ошибочных HTTP-кодах или некорректном JSON бросает `LLMError`.

## Внутренние функции

- `_is_openai_mode(base_url)` — определение режима по URL.
- `_ollama_chat_url`, `_ollama_tags_url`, `_openai_chat_url`, `_openai_models_url` — построение URL.
- `_auth_headers(api_key)` — формирует заголовок `Authorization`, если ключ непустой.
- `_chat_ollama(...)`, `_check_ollama(...)` — реализация Ollama-режима.
- `_chat_openai(...)`, `_check_openai(...)` — реализация OpenAI-совместимого режима.

## Зависимости

- `from __future__ import annotations` — отложенная аннотация типов.
- `logging` — логирование предупреждений (`num_ctx`, 404 на `/models`).
- `requests` — HTTP-запросы `POST` и `GET`, обработка `Timeout` и `RequestException`.

Модуль не импортирует другие модули проекта.

## Использование в проекте

Модуль выступает низкоуровневым слоем доступа к LLM. В изолированном файле импорты других модулей проекта отсутствуют, поэтому связи видны только по существующей документации:

- `cli.py` вызывает `check_model(...)` при проверке доступности сервера и получении списка моделей для отображения пользователю; сопоставление имени модели выполняет сам `cli.py`.
- Предполагаемый вызов `chat(...)` — для отправки промптов в LLM в основном рабочем потоке.

Обе публичные функции пробрасывают `LLMError`; перехват и формирование пользовательского сообщения выполняются на стороне вызывающего кода.

## Примечания и ограничения

- Публичный контракт `chat(...)`: `HTTP != 200`, отсутствие `choices[0].message.content` в OpenAI-режиме или `message.content` в Ollama-режиме, пустой `content` → `LLMError`.
- Тело ответа в `LLMError.body` обрезается до 1000 символов.
- В OpenAI-режиме `num_ctx` не передаётся — размер контекста определяет сервер.
- Авторизация поддерживается только в OpenAI-режиме; Ollama-эндпоинты вызываются без заголовков авторизации.
- Для OpenAI-совместимых прокси без `/v1/models` проверка имён моделей возвращает `[]` и сопровождается предупреждением при 404. При HTTP 200 с пустым или невалидным списком моделей также возвращается `[]`.
- `check_model(...)` не проверяет наличие конкретной `model` в списке; это делает вызывающая сторона.
