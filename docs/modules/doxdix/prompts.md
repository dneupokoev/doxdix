# Шаблоны промптов для LLM

## Назначение

Модуль содержит русскоязычные шаблоны промптов для генерации и обновления документации проекта с помощью LLM:

- `docs/SUMMARY.md`;
- `README.md`;
- документации отдельных модулей;
- содержимого `CHANGELOG.md`.

Также модуль предоставляет функцию `render` для подстановки значений в шаблоны.

Все промпты требуют возвращать полный текст `.md`, а не diff и не фрагмент. Тексты соответствуют ТЗ п. 7.1–7.4 с усилениями v12: `project_context` в `SUMMARY` и `README`, запрет выдумывать команды/флаги, запрет обрамляющих блоков кода.

Версия файла: `dv_file_version = '261028.15'`.

## Публичный API

- `SUMMARY_PROMPT`
- `SUMMARY_FINAL_PROMPT`
- `README_PROMPT`
- `MODULE_PROMPT`
- `CHANGELOG_LLM_PROMPT`
- `render(template, **kwargs) -> str`

Классов в модуле нет.

## Шаблоны промптов

### `SUMMARY_PROMPT`

Промпт для создания или дополнения `docs/SUMMARY.md`.

Использует параметры:

- `project_context` — первые строки `README.md`, могут быть пустыми;
- `file_list` — список файлов проекта;
- `existing_content` — текущее содержимое `SUMMARY.md`, может быть пустым.

Требует:

- создать структурированный обзор проекта: назначение, основные модули, их роль;
- опираться только на `README.md` и список файлов;
- не выдумывать назначение проекта, если его нет в `README.md`, и не додумывать его по названию;
- добавлять ссылки на документацию модулей в формате `[имя](modules/<подпуть>.md)`, где подпуть — полный путь от `docs/`;
- сохранять все существующие разделы и ссылки, ничего не удалять;
- не делать `SUMMARY` копией `README`: это оглавление и краткий обзор;
- не дублировать разделы «Установка» и «Использование» целиком;
- не добавлять раздел про лицензию;
- писать лаконично, структурировано, на русском языке;
- возвращать только текст Markdown без обрамляющих блоков кода.

### `SUMMARY_FINAL_PROMPT`

Промпт для финального дополнения `docs/SUMMARY.md` ссылками на созданные файлы документации (шаг 5, ТЗ п. 6.7).

Использует параметры:

- `file_list` — пути созданных/обновлённых `.md` относительно `docs/`, например `modules/doxdix/backup.md`;
- `existing_content` — текущее содержимое `SUMMARY.md`, может быть пустым.

Требует:

- добавлять ссылки только на те файлы документации, которых в `SUMMARY.md` ещё нет;
- использовать формат `[имя](<путь>)`, где `<путь>` уже относительный к `docs/`;
- использовать путь из `file_list` как есть: не добавлять префикс `docs/` и не менять структуру папок;
- сохранять все существующие разделы и ссылки, ничего не удалять;
- не добавлять разделы «Установка», «Использование», «Быстрый старт»;
- не добавлять раздел про лицензию;
- писать лаконично, структурировано, на русском языке;
- возвращать только текст Markdown без обрамляющих блоков кода.

### `README_PROMPT`

Промпт для обновления `README.md`.

Использует параметры:

- `project_context` — первые строки `README.md`;
- `file_list` — список файлов проекта;
- `recent_commits` — последние коммиты для контекста;
- `existing_content` — текущее содержимое `README.md`, может быть пустым.

Требует:

- обновлять разделы, описывающие код: назначение, установку, использование, структуру;
- опираться на существующий `README.md` и список файлов;
- не выдумывать команды и флаги, которых нет в `README.md`;
- сохранять все вручную написанные разделы: примеры, ограничения, контрибьютинг, благодарности;
- сохранять примеры запуска с конкретными флагами (`--model`, `--ollama-url`, `--check`, `--restore` и т.п.), если они есть в существующем `README.md`;
- не заменять конкретные примеры общими словами;
- если есть сомнения, удалять ли раздел, — оставлять его;
- не добавлять раздел про лицензию;
- если раздел про лицензию уже есть в существующем `README.md`, оставить его без изменений;
- писать лаконично, структурировано, на русском языке;
- возвращать только текст Markdown без обрамляющих блоков кода.

### `MODULE_PROMPT`

Промпт для изолированного анализа отдельного файла кода и существующей документации модуля.

Использует параметры:

- `code_content` — содержимое файла кода;
- `existing_content` — существующая документация модуля, может быть пустой.

Требует:

- обновить описание кода: главное назначение модуля, основные функции/классы и их аргументы, зависимости от других модулей из импортов;
- сохранять все разделы существующей документации, которые не противоречат коду: примеры использования, ограничения, заметки автора;
- если есть сомнения, удалять ли раздел, — оставлять его;
- описывать, как этот модуль используется другими модулями проекта, если это видно из импортов и вызовов;
- писать лаконично, структурировано, на русском языке;
- возвращать только текст Markdown без обрамляющих блоков кода.

### `CHANGELOG_LLM_PROMPT`

Промпт для переписывания сгруппированных git-коммитов в user-facing формулировки для `CHANGELOG.md`.

Использует параметр:

- `grouped_commits` — изменения, сгруппированные по типам.

Требует:

- сохранять все факты;
- не добавлять ничего, чего нет в исходном списке;
- не менять группировку по секциям `Added`, `Fixed`, `Changed` и т.п.;
- писать на русском языке, лаконично;
- возвращать только содержимое секции `[Unreleased]` в формате Markdown.

## Функция `render`

Сигнатура: `render(template: str, **kwargs: object) -> str`

Подставляет именованные аргументы `kwargs` в строку `template` через `str.format` и возвращает результат.

Особенности:

- шаблоны заданы обычными строками, а не f-строками;
- подстановка выполняется только в момент вызова `render`;
- фигурные скобки в уже подставленных значениях повторно не интерпретируются;
- если в самом шаблоне потребуются литеральные фигурные скобки, их нужно будет экранировать; в текущих шаблонах таких мест нет.

## Зависимости

- `from __future__ import annotations` — стандартная библиотека Python.
- Других импортов нет.
- Внешние зависимости отсутствуют.

## Использование другими модулями

В изолированном файле нет импортов других модулей проекта, поэтому конкретные места вызова по этому файлу не видны. Модуль предназначен для импорта констант промптов и функции `render` из других частей проекта.

## Замечания

- Все промпты требуют возвращать полный Markdown-текст, а не diff и не фрагмент.
- В промптах заложены ограничения против выдумывания фактов, команд, флагов и назначения проекта.
- Для `SUMMARY_PROMPT` и `README_PROMPT` отдельно подчёркнуто сохранение существующих разделов.
- `MODULE_PROMPT` требует сохранять существующую документацию модуля, если она не противоречит коду.
- `project_context` в `SUMMARY_PROMPT` и `README_PROMPT` помогает модели не выдумывать назначение проекта.
- Все промпты требуют возвращать только текст `.md`, без обрамляющих блоков кода.
