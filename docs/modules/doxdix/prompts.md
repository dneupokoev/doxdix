# Шаблоны промптов для LLM

## Назначение

Модуль содержит русскоязычные шаблоны промптов для генерации и обновления документации проекта с помощью LLM:

- `docs/SUMMARY.md`;
- `README.md`;
- документации отдельных модулей;
- содержимого `CHANGELOG.md`.

Также модуль предоставляет функцию `render` для подстановки значений в шаблоны.

Версия файла: `dv_file_version = '261028.12'`.

## Публичный API

- `SUMMARY_PROMPT`
- `README_PROMPT`
- `MODULE_PROMPT`
- `CHANGELOG_LLM_PROMPT`
- `render(template, **kwargs) -> str`

Классов в модуле нет.

## Шаблоны промптов

### `SUMMARY_PROMPT`

Промпт для создания или дополнения `docs/SUMMARY.md`.

Использует параметры:

- `project_context` — первые строки `README.md`;
- `file_list` — список файлов проекта;
- `existing_content` — текущее содержимое `SUMMARY.md`.

Требует:

- описывать проект только на основе `README.md` и списка файлов;
- не выдумывать назначение проекта;
- добавлять ссылки на документацию модулей в формате `modules/<полный_путь_от_docs>.md`;
- сохранять существующие разделы и ссылки;
- возвращать только текст Markdown без обрамляющих блоков кода.

### `README_PROMPT`

Промпт для обновления `README.md`.

Использует параметры:

- `project_context` — первые строки `README.md`;
- `file_list` — список файлов проекта;
- `recent_commits` — последние коммиты для контекста;
- `existing_content` — текущее содержимое `README.md`.

Требует:

- обновлять разделы, описывающие код;
- не выдумывать команды и флаги, которых нет в `README.md`;
- сохранять вручную написанные разделы;
- при сомнениях оставлять раздел;
- не добавлять раздел про лицензию;
- возвращать только текст Markdown без обрамляющих блоков кода.

### `MODULE_PROMPT`

Промпт для анализа отдельного файла кода и существующей документации модуля.

Использует параметры:

- `code_content` — содержимое файла кода;
- `existing_content` — существующая документация модуля.

Требует:

- описывать назначение модуля;
- перечислять основные функции/классы и их аргументы;
- указывать зависимости из импортов;
- сохранять существующие разделы документации, если они не противоречат коду;
- при сомнениях оставлять раздел;
- описывать использование модуля другими модулями, если это видно из импортов и вызовов;
- возвращать только текст Markdown без обрамляющих блоков кода.

### `CHANGELOG_LLM_PROMPT`

Промпт для переписывания сгруппированных git-коммитов в user-facing формулировки для `CHANGELOG.md`.

Использует параметр:

- `grouped_commits` — изменения, сгруппированные по типам.

Требует:

- сохранять все факты;
- не добавлять ничего, чего нет в исходном списке;
- не менять группировку по секциям `Added`, `Fixed`, `Changed` и т.п.;
- писать на русском языке и лаконично;
- возвращать только содержимое секции `[Unreleased]` в формате Markdown.

## Функция `render`

```text
render(template: str, **kwargs: object) -> str
```

Подставляет именованные аргументы `kwargs` в строку `template` через `str.format` и возвращает результат.

Особенности:

- шаблоны заданы обычными строками, а не f-строками;
- подстановка выполняется только в момент вызова `render`;
- фигурные скобки в уже подставленных значениях повторно не интерпретируются;
- если в самом шаблоне потребуются литеральные фигурные скобки, их нужно будет экранировать; в текущих шаблонах таких мест нет.

## Зависимости

- `from __future__ import annotations` — стандартная библиотека Python.
- Других импортов нет.
- Внешние зависимости отсутствуют.

## Использование другими модулями

В изолированном файле нет импортов других модулей проекта, поэтому конкретные места вызова по этому файлу не видны. Модуль предназначен для импорта констант промптов и функции `render` из других частей проекта.

## Замечания

- Все промпты требуют возвращать полный Markdown-текст, а не diff и не фрагмент.
- В промптах заложены ограничения против выдумывания фактов, команд, флагов и назначения проекта.
- Для `SUMMARY_PROMPT` и `README_PROMPT` отдельно подчёркнуто сохранение существующих разделов.
- `MODULE_PROMPT` требует сохранять существующую документацию модуля, если она не противоречит коду.
