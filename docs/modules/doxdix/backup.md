# Модуль бэкапа документации

## Назначение

Модуль отвечает за создание, восстановление и ротацию резервных копий документации проекта. Бэкап размещается в каталоге `<backup_dir>/<ISO-timestamp>/` и включает:

- `README.md`;
- `CHANGELOG.md`;
- всё содержимое каталога `docs/`;
- `manifest.json` с метаданными скопированных файлов.

Модуль содержит версию `dv_file_version = '261028.03'` и использует модульный логгер `logger`.

## Публичный API

- `create_backup(project_root: Path, backup_dir: Path, keep: int) -> Path | None`
- `restore_backup(project_root: Path, backup_dir: Path, timestamp: str) -> int | None`
- `list_backups(backup_dir: Path) -> list[str]`

## Основные функции

### `create_backup(project_root, backup_dir, keep)`

Создаёт резервную копию документации.

Аргументы:

- `project_root` — корневой каталог проекта, откуда берутся `README.md`, `CHANGELOG.md` и `docs/`;
- `backup_dir` — каталог, в котором создаются папки бэкапов;
- `keep` — сколько последних бэкапов оставить после ротации.

Поведение:

- собирает файлы `README.md`, `CHANGELOG.md` и всё содержимое `docs/`, если они существуют;
- если копировать нечего, логирует это и возвращает `None`;
- создаёт `backup_dir` при необходимости;
- создаёт каталог бэкапа с timestamp вида `YYYY-MM-DDTHH-MM-SS`;
- при совпадении имени добавляет суффиксы `-1`, `-2`, ...;
- копирует файлы с сохранением относительных путей;
- формирует `manifest.json` со списком успешно скопированных файлов и их SHA-256;
- после успешной записи `manifest.json` выполняет ротацию;
- при критических ошибках создания каталогов или записи `manifest.json` логирует ошибку и возвращает `None`;
- ошибки копирования отдельных файлов логируются, но не прерывают создание бэкапа: бэкап может получиться частичным.

### `restore_backup(project_root, backup_dir, timestamp)`

Восстанавливает файлы из указанного бэкапа.

Аргументы:

- `project_root` — корневой каталог проекта, куда восстанавливаются файлы;
- `backup_dir` — каталог с бэкапами;
- `timestamp` — имя папки бэкапа.

Поведение:

- ищет каталог `backup_dir / timestamp` и `manifest.json`;
- если бэкап или `manifest.json` отсутствует, возвращает `None`;
- если `manifest.json` не читается или содержит некорректный JSON, возвращает `None`;
- читает список файлов из `manifest.json`;
- копирует файлы обратно в `project_root`;
- при отсутствии отдельного файла в бэкапе логирует предупреждение и продолжает;
- при ошибке копирования отдельного файла логирует ошибку и продолжает;
- отсутствующие в бэкапе файлы проекта не удаляет;
- возвращает число успешно восстановленных файлов; при ошибках копирования это число может быть меньше ожидаемого, в том числе `0`;
- `None` возвращается при отсутствии бэкапа, отсутствии `manifest.json` или ошибке чтения/разбора manifest.

### `list_backups(backup_dir)`

Возвращает список имён существующих бэкапов.

Поведение:

- если каталог не существует, возвращает пустой список;
- учитывает только директории;
- исключает имена, начинающиеся с `.`;
- сортирует имена в обратном лексикографическом порядке, то есть свежие бэкапы идут первыми;
- не проверяет наличие и корректность `manifest.json`.

## Внутренние функции

- `_iso_timestamp()` — формирует текущий timestamp в формате `YYYY-MM-DDTHH-MM-SS`.
- `_sha256(path)` — вычисляет SHA-256 файла потоково, блоками по 65536 байт.
- `_unique_backup_dir(backup_dir)` — подбирает свободное имя каталога бэкапа с учётом суффиксов при коллизии.
- `_rotate(backup_dir, keep)` — удаляет старые бэкапы, оставляя `keep` последних.
- `_collect_backup_targets(project_root)` — собирает относительные пути файлов для бэкапа.

## Формат manifest.json

`manifest.json` имеет структуру:

    {
      "timestamp": "...",
      "files": [
        {
          "path": "...",
          "sha256": "..."
        }
      ]
    }

Поле `timestamp` содержит имя папки бэкапа. Поле `files` содержит относительные пути скопированных файлов и их SHA-256. В список попадают только файлы, которые удалось скопировать.

## Ротация

Ротация выполняется после успешного создания бэкапа и записи `manifest.json`. Оставляются последние `keep` бэкапов по сортировке имён папок. Если `keep <= 0`, ротация не выполняется. Если бэкапов меньше или равно `keep`, ничего не удаляется. Ошибки удаления логируются, но не прерывают работу.

## Зависимости

Модуль использует только стандартную библиотеку Python:

- `hashlib` — вычисление SHA-256;
- `json` — чтение и запись manifest;
- `logging` — логирование;
- `shutil` — копирование и удаление каталогов;
- `datetime` — формирование timestamp;
- `pathlib` — работа с путями;
- `__future__.annotations` — отложенная аннотация типов.

Внутренних зависимостей от других модулей проекта в данном файле нет.

## Использование другими модулями

В предоставленном файле нет импортов и вызовов, которые показывали бы конкретных потребителей модуля. Предполагаемое использование другими модулями проекта — через публичный API:

- импорт `create_backup` для создания резервной копии документации;
- импорт `restore_backup` для восстановления документации;
- импорт `list_backups` для получения списка доступных бэкапов.

## Ограничения и особенности

- Бэкапятся только `README.md`, `CHANGELOG.md` и содержимое `docs/`.
- При восстановлении отсутствующие в бэкапе файлы проекта не удаляются.
- При восстановлении не выполняется проверка SHA-256 из manifest.
- Пути из `manifest.json` используются как относительные пути при восстановлении; проверка на абсолютные пути или выход за пределы `project_root` отсутствует.
- Ошибки копирования и записи логируются. Для `create_backup` критические ошибки приводят к `None`; при ошибках копирования отдельных файлов бэкап может быть создан частично.
- Для `restore_backup` ошибки копирования отдельных файлов не прерывают восстановление, а возвращается число успешно восстановленных файлов.
- При ошибке записи `manifest.json` каталог бэкапа может остаться частично созданным.
- `list_backups` не проверяет наличие `manifest.json`, а просто возвращает имена подходящих директорий.
