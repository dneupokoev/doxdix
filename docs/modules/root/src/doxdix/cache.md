# Кэш SHA-256 исходного кода

## Назначение

Модуль ведёт кэш SHA-256 хэшей исходного кода в файле `<project>/.doxdix/cache.json`. Кэш нужен, чтобы не отправлять в LLM файлы, код которых не менялся с прошлого запуска, и тем самым экономить токены и время.

Формат файла — JSON-объект вида:

`{"<подпроект>/<относительный/путь.py>": "<sha256 в hex>"}`

Ключ включает подпроект, поэтому одинаковые относительные пути из разных подпроектов монорепо не перетирают друг друга. Для корневого проекта используется префикс `root/`. В режиме `--no-monorepo` ключ — просто путь от корня проекта.

При `RunConfig.force` кэш игнорируется; это связано с флагом `--force` в `cli.py`.

## Расположение и константы

- `CACHE_DIR = ".doxdix"` — каталог кэша внутри проекта.
- `CACHE_FILENAME = "cache.json"` — имя файла кэша.
- `dv_file_version = "261028.19"` — версия/маркер файла модуля.
- `_READ_CHUNK = 1024 * 1024` — размер порции чтения файла при вычислении хэша.

Файл кэша располагается по пути `<project>/.doxdix/cache.json`.

## Публичный API

### `cache_file_path(project_root: Path) -> Path`

Возвращает путь к файлу кэша: `project_root / ".doxdix" / "cache.json"`.

### `file_sha256(code_path: Path) -> str | None`

Вычисляет SHA-256 содержимого файла и возвращает hex-строку. Файл читается порциями по `1 MiB`, поэтому содержимое не загружается в память целиком.

При `OSError` логирует предупреждение и возвращает `None`.

### `class Cache`

Хранит хэши содержимого файлов, загруженные из `.doxdix/cache.json`. Отсутствующий или повреждённый файл кэша не считается фатальной ошибкой: кэш просто создаётся пустым. Запись на диск выполняется только при наличии изменений.

#### `__init__(project_root: Path, data: dict[str, str] | None = None) -> None`

Создаёт объект кэша:
- сохраняет путь к файлу кэша;
- копирует переданные данные в `_data`;
- устанавливает `_dirty = False`.

#### `load(project_root: Path) -> Cache`

Читает кэш из файла. Если файл отсутствует, не читается, содержит невалидный JSON или JSON-значение не является объектом, возвращает пустой `Cache`. Для проблем чтения/парсинга пишет предупреждение в лог. Ключи и значения приводятся к строкам.

#### `get(rel_key: str) -> str | None`

Возвращает сохранённый хэш по относительному ключу в posix-формате или `None`, если записи нет.

#### `set(rel_key: str, sha: str) -> None`

Запоминает хэш файла. Если значение отличается от уже сохранённого, помечает кэш как изменённый. Фактическая запись произойдёт только в `save()`.

#### `is_unchanged(rel_key: str, sha: str, md_path: Path) -> bool`

Возвращает `True`, если:
- итоговый `.md`-файл уже существует (`md_path.is_file()`);
- хэш в кэше совпадает с переданным `sha`.

То есть одного совпадения хэша недостаточно: результат предыдущего запуска должен присутствовать на диске.

#### `save() -> bool`

Записывает кэш, если были изменения. Если изменений нет, сразу возвращает `True`. При записи:
- создаёт родительский каталог при необходимости;
- пишет JSON с `ensure_ascii=False`, `indent=2`, `sort_keys=True` и завершающим переводом строки;
- при `OSError` логирует предупреждение и возвращает `False`.

При успешной записи сбрасывает признак изменённости и возвращает `True`.

## Зависимости

Используются только стандартные модули Python:

- `__future__` — включение аннотаций нового стиля;
- `hashlib` — вычисление SHA-256;
- `json` — чтение и запись JSON-кэша;
- `logging` — диагностические сообщения;
- `pathlib` — работа с путями.

Импортов из других модулей проекта в этом файле нет.

## Использование в проекте

Судя по docstring, модуль используется оркестратором и CLI:

- `orchestrator._step_modules`, вероятно, формирует ключи с учётом подпроекта и использует кэш для пропуска неизменённых файлов;
- `cli.py` через `RunConfig.force` и флаг `--force` может отключать использование кэша.

Типовой сценарий:
1. загрузить кэш через `Cache.load(project_root)`;
2. вычислить текущий хэш файла через `file_sha256(path)`;
3. проверить `is_unchanged(rel_key, sha, md_path)` или сравнить через `get`;
4. для изменённых файлов выполнить обработку и сохранить новый хэш через `set`;
5. записать изменения через `save()`.

## Ограничения и поведение

- Ошибки чтения отдельного файла при вычислении хэша не фатальны: возвращается `None`.
- Повреждённый или отсутствующий файл кэша не прерывает работу: кэш считается пустым.
- `save()` не пишет файл, если не было вызовов `set()` с новыми значениями.
- `is_unchanged()` учитывает не только хэш, но и наличие итогового `.md`-файла.
- Ключи кэша должны быть согласованы между режимами монорепо и `--no-monorepo`, иначе записи не будут находиться.
