# Модуль бэкапа документации

## Назначение

Модуль создаёт, восстанавливает и перечисляет резервные копии документации проекта. Бэкап включает `README.md`, `CHANGELOG.md` и всё содержимое каталога `docs/`, если они существуют.

Каждый бэкап размещается в отдельном каталоге:

`<backup_dir>/<ISO-timestamp>/`

Timestamp имеет вид `2026-10-28T14-30-00` — двоеточия заменены на дефисы. При коллизии имени каталога добавляется суффикс `-1`, `-2`, ....

В каталоге бэкапа создаётся `manifest.json` со структурой:

`{"timestamp": "...", "files": [{"path": "...", "sha256": "..."}]}`

## Публичный API

### `create_backup(project_root: Path, backup_dir: Path, keep: int) -> Path | None`

Создаёт бэкап документации.

Аргументы:
- `project_root` — корень проекта, откуда копируются `README.md`, `CHANGELOG.md` и `docs/`.
- `backup_dir` — каталог, в котором создаются резервные копии.
- `keep` — сколько последних бэкапов оставить после ротации.

Возвращает:
- `Path` созданного каталога бэкапа;
- `None`, если копировать нечего или возникла фатальная ошибка создания каталога/`manifest.json`.

Особенности:
- пути `project_root` и `backup_dir` приводятся к абсолютным через `resolve()`;
- если нет `README.md`, `CHANGELOG.md` и `docs/`, бэкап не создаётся;
- ошибки копирования отдельных файлов логируются, но не прерывают процесс;
- в `manifest.json` попадают только успешно скопированные файлы;
- ротация выполняется после успешной записи `manifest.json`.

### `restore_backup(project_root: Path, backup_dir: Path, timestamp: str) -> int | None`

Восстанавливает файлы из бэкапа.

Аргументы:
- `project_root` — корень проекта, куда копируются файлы.
- `backup_dir` — каталог с бэкапами.
- `timestamp` — имя каталога бэкапа.

Возвращает:
- число восстановленных файлов;
- `None`, если бэкап не найден, `manifest.json` отсутствует или повреждён.

Особенности:
- файлы, отсутствующие в бэкапе, в проекте не удаляются;
- отсутствующие в бэкапе файлы из manifest пропускаются с предупреждением;
- ошибки копирования отдельных файлов логируются и не прерывают восстановление;
- SHA-256 из manifest при восстановлении не проверяется;
- пути из manifest дополнительно не валидируются.

### `list_backups(backup_dir: Path) -> list[str]`

Возвращает список timestamp-каталогов существующих бэкапов.

Особенности:
- учитываются только каталоги;
- скрытые каталоги, начинающиеся с `.`, игнорируются;
- сортировка обратная лексикографическая, то есть «свежие сверху» в пределах ожидаемого формата имён.

## Внутренние функции

- `_iso_timestamp() -> str` — формирует текущий timestamp для имени каталога бэкапа.
- `_sha256(path: Path) -> str` — считает SHA-256 файла.
- `_unique_backup_dir(backup_dir: Path) -> tuple[str, Path]` — подбирает свободное имя каталога с учётом суффиксов `-1`, `-2`, ....
- `_rotate(backup_dir: Path, keep: int) -> None` — удаляет старые бэкапы, оставляя `keep` последних. При `keep <= 0` ротация не выполняется.
- `_collect_backup_targets(project_root: Path) -> list[Path]` — собирает относительные пути файлов для бэкапа.

## Зависимости

Используются только стандартная библиотека Python:
- `hashlib` — расчёт SHA-256;
- `json` — чтение и запись `manifest.json`;
- `logging` — логирование;
- `shutil` — копирование файлов и удаление каталогов;
- `datetime.datetime` — формирование timestamp;
- `pathlib.Path` — работа с путями;
- `__future__.annotations` — отложенная аннотация типов.

Внутренних зависимостей от других модулей проекта в файле нет.

## Использование другими модулями проекта

В изолированном файле нет импортов данного модуля другими модулями, поэтому конкретные потребители не видны. Предполагаемое использование — через публичный API:

- `create_backup(...)` — при необходимости сохранить состояние документации;
- `restore_backup(...)` — для отката документации к выбранному бэкапу;
- `list_backups(...)` — для получения списка доступных бэкапов перед восстановлением или ротацией.

## Ограничения и заметки

- Ротация сортирует имена каталогов лексикографически. Для штатного формата timestamp это работает предсказуемо; при большом числе коллизий в одну секунду суффиксы `-10`, `-11` и т.п. могут сортироваться не в числовом порядке.
- `create_backup` не удаляет частично созданный каталог, если запись `manifest.json` не удалась.
- `restore_backup` не проверяет целостность файлов по SHA-256, хотя хеши сохраняются в manifest.
- `restore_backup` доверяет относительным путям из manifest и не выполняет дополнительную защиту от абсолютных путей или выхода за пределы `project_root`.
- Ошибки в большинстве операций логируются и не приводят к исключениям, чтобы не останавливать конвейер.
