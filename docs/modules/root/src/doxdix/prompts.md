# Модуль `prompts`

## Назначение

Модуль содержит централизованные шаблоны промптов для LLM, используемые при создании и обновлении документации проекта:

- `docs/SUMMARY.md`;
- `README.md`;
- документации отдельных модулей;
- `CHANGELOG.md`.

Все промпты написаны на русском языке и требуют от модели вернуть полный текст `.md`, а не diff, фрагмент или содержимое в обрамляющем блоке кода.

## Публичный API

В docstring модуля как публичный API указаны:

- `SUMMARY_PROMPT`;
- `SUMMARY_FINAL_PROMPT`;
- `README_PROMPT`;
- `MODULE_PROMPT`;
- `CHANGELOG_LLM_PROMPT`;
- `render(template, **kwargs) -> str`.

Дополнительно в модуле определена переменная `dv_file_version = '261028.17'`.

## Константы промптов

### `SUMMARY_PROMPT`

Шаблон для создания или дополнения файла `docs/SUMMARY.md`.

Плейсхолдеры:

- `project_context` — первые строки `README.md`;
- `modules_content` — содержимое уже созданных `.md`-файлов документации модулей;
- `existing_content` — существующий `SUMMARY.md`.

Основные требования к модели:

- опираться только на `README.md` и содержимое документации модулей;
- не выдумывать назначение проекта;
- сохранять существующие разделы и ссылки;
- использовать пути к файлам как есть, относительно `docs/`;
- не добавлять раздел про лицензию;
- вернуть только текст `.md`.

### `SUMMARY_FINAL_PROMPT`

Шаблон для финального дополнения `docs/SUMMARY.md` ссылками на созданные или обновлённые файлы документации.

Плейсхолдеры:

- `modules_content` — содержимое созданных или обновлённых `.md`-файлов;
- `existing_content` — существующий `SUMMARY.md`.

Основные требования:

- добавить ссылки на файлы, которых ещё нет в `SUMMARY.md`;
- сохранить существующие разделы и ссылки;
- уточнять назначение модулей по содержимому документации, а не только по именам файлов;
- не добавлять разделы «Установка», «Использование», «Быстрый старт»;
- не добавлять раздел про лицензию;
- вернуть только текст `.md`.

### `README_PROMPT`

Шаблон для обновления `README.md`.

Плейсхолдеры:

- `project_context` — первые строки `README.md`;
- `file_list` — список файлов проекта;
- `recent_commits` — последние коммиты для контекста;
- `existing_content` — существующий `README.md`.

Основные требования:

- обновлять разделы, описывающие код: назначение, установку, использование, структуру;
- не выдумывать команды и флаги, которых нет в существующем `README.md`;
- сохранять вручную написанные разделы;
- сохранять конкретные примеры запуска с флагами;
- при сомнениях оставлять раздел;
- не добавлять раздел про лицензию, если его нет, и не менять существующий раздел про лицензию;
- вернуть только текст `.md`.

### `MODULE_PROMPT`

Шаблон для анализа отдельного файла кода и существующей документации модуля.

Плейсхолдеры:

- `code_content` — содержимое файла кода;
- `existing_content` — существующая документация модуля.

Основные требования:

- описать главное назначение модуля;
- перечислить основные функции и классы, их аргументы;
- указать зависимости от других модулей по импортам;
- сохранить разделы существующей документации, не противоречащие коду;
- при сомнениях оставлять раздел;
- описать использование модуля другими модулями проекта, если это видно из импортов и вызовов;
- вернуть только текст `.md`.

### `CHANGELOG_LLM_PROMPT`

Шаблон для переписывания сгруппированных изменений из git-коммитов в user-facing формулировки для `CHANGELOG.md`.

Плейсхолдер:

- `grouped_commits` — изменения, сгруппированные по типам.

Основные требования:

- сохранить все факты и не добавлять ничего, чего нет в списке;
- не менять группировку по секциям `Added` / `Fixed` / `Changed` и т.п.;
- писать на русском языке, лаконично;
- вернуть только содержимое секции `[Unreleased]` в формате Markdown.

## Функции

### `render(template: str, **kwargs: object) -> str`

Подставляет переданные именованные аргументы в шаблон через `str.format` и возвращает итоговую строку.

Особенность реализации: модуль намеренно не использует f-строки и не вызывает `format` на самих шаблонах. Это предотвращает обработку фигурных скобок внутри уже подставленного содержимого, например кода или `README.md`. Риск остаётся только для фигурных скобок в самих шаблонах, но в текущих шаблонах их нет.

## Зависимости

- `from __future__ import annotations` — для отложенной оценки аннотаций.
- Импортов других модулей проекта нет.
- Внешних зависимостей нет.

## Использование другими модулями

В изолированном файле нет импортов и вызовов, поэтому конкретные места использования не видны. Модуль предоставляет константы промптов и функцию `render` как публичный API для внешнего кода генерации и обновления документации.

## Примечания

- `dv_file_version = '261028.17'` — версия файла/модуля.
- Шаблоны содержат именованные плейсхолдеры, подставляемые через `render`.
- В промптах явно запрещено возвращать содержимое в обрамляющих блоках кода и с обёрткой `markdown`.
- Существующая документация для данного модуля отсутствует, поэтому сохранять дополнительные разделы не требовалось.
