# Модуль сканирования проекта

## Назначение

Модуль отвечает за сканирование файлов проекта и подготовку данных для дальнейшей обработки:

- обход файловой системы или использование списка файлов, отслеживаемых git;
- фильтрация по расширениям и исключениям;
- сбор git-данных: последние коммиты и множество отслеживаемых файлов;
- поддержка монорепозиториев: поиск корней подпроектов и группировка файлов по ближайшему подпроекту.

Публичный API описан в docstring модуля: `scan`, `scan_grouped`, `find_subproject_roots`, `group_by_subproject`, `subproject_root`, `ROOT_SUBPROJECT`.

Версия файла: `dv_file_version = '261028.03'`.

## Зависимости

Модуль использует только стандартную библиотеку Python:

- `__future__.annotations`
- `logging`
- `subprocess`
- `dataclasses.dataclass`, `dataclasses.field`
- `pathlib.Path`
- локально импортируемые `fnmatch.fnmatch` и `re`

Импортов других модулей проекта в файле нет. Модуль выглядит самодостаточным.

## Константы

- `DEFAULT_EXCLUDE_DIRS` — набор директорий, исключаемых по умолчанию: `.git`, `.doxdix`, `node_modules`, `__pycache__`, `venv`, `.venv`, `env`, `dist`, `build`, `tests`, `test`, `.mypy_cache`, `.pytest_cache`, `.ruff_cache`, `target`.
- `DEFAULT_EXCLUDE_FILE_PATTERNS` — паттерны файлов, исключаемых по умолчанию: `test_*`, `*_test.*`, `*.min.*`, `*.spec.*`, `conftest.py`.
- `SUBPROJECT_MARKERS` — файлы-маркеры корня подпроекта: `pyproject.toml`, `package.json`, `Cargo.toml`, `go.mod`.
- `ROOT_SUBPROJECT = "root"` — ключ корневого проекта и файлов вне известных подпроектов.

## Модели данных

### `GitCommit`

Frozen dataclass, описывает один коммит:

- `sha: str` — SHA коммита;
- `subject: str` — тема коммита;
- `body: str` — тело коммита.

### `GitData`

Dataclass результата сбора git-данных:

- `has_git: bool = False` — доступны ли git-данные;
- `commits: list[GitCommit]` — список коммитов;
- `tracked_files: set[str]` — относительные пути файлов, отслеживаемых git.

## Публичный API

### `scan(...)`

```text
scan(project_root, src_dir, extensions, user_excludes, use_git, changelog_limit)
    -> tuple[list[Path], GitData]
```

Сканирует проект и возвращает список абсолютных путей файлов и `GitData`.

Аргументы:

- `project_root: Path` — корень целевого проекта. Должен быть директорией; путь разрешается через `resolve()`.
- `src_dir: str | None` — относительная подпапка с кодом. Если задана, должна существовать и быть директорией.
- `extensions: list[str]` — список расширений, например `['.py', '.ts']`. Нормализуются: приводятся к нижнему регистру и получают ведущую точку.
- `user_excludes: list[str]` — пользовательские исключения из `--exclude`: имена директорий и/или glob-паттерны файлов.
- `use_git: bool` — если `False`, git-данные не собираются.
- `changelog_limit: int` — сколько последних коммитов запрашивать для CHANGELOG.

Поведение:

- Если `extensions` после нормализации пуст, возвращает `([], GitData(has_git=False))`.
- Если git доступен и `git ls-files` вернул непустой список, используются только отслеживаемые файлы.
- Если git недоступен, отключён или список отслеживаемых файлов пуст, выполняется рекурсивный обход файловой системы.
- Итоговый список файлов сортируется по строковому пути.
- При некорректном `project_root` или `src_dir` поднимает `ValueError`.

### `scan_grouped(...)`

```text
scan_grouped(project_root, src_dir, extensions, user_excludes, use_git, changelog_limit)
    -> tuple[dict[str, list[Path]], GitData]
```

Работает как `scan()`, но результат дополнительно группируется по подпроектам через `group_by_subproject()`.

Ключ группы — относительный путь корня подпроекта от `project_root`; для корневого проекта и файлов вне известных подпроектов используется `"root"`.

### `find_subproject_roots(project_root, user_excludes)`

```text
find_subproject_roots(project_root: Path, user_excludes: list[str]) -> list[Path]
```

Находит абсолютные пути каталогов-корней подпроектов.

Корнем считается директория, содержащая хотя бы один файл из `SUBPROJECT_MARKERS`. Обход начинается с `project_root`; сам корень тоже может быть подпроектом.

Правила обхода:

- символические ссылки пропускаются;
- скрытые директории, имя которых начинается с `.`, пропускаются;
- директории из `DEFAULT_EXCLUDE_DIRS` и `user_excludes` пропускаются;
- для `user_excludes` при поиске директорий поддерживаются точное совпадение имени и glob-паттерны;
- ошибки доступа к директории логируются как warning и не прерывают поиск;
- результат сортируется по `as_posix()`.

### `group_by_subproject(files, project_root, user_excludes)`

```text
group_by_subproject(files: list[Path], project_root: Path, user_excludes: list[str])
    -> dict[str, list[Path]]
```

Группирует файлы по ближайшему (самому глубокому) корню подпроекта-предка.

Правила:

- ключ `"root"` используется для корневого проекта и файлов вне известных подпроектов;
- если файл находится вне `project_root`, он также попадает в `"root"`;
- группы упорядочены: `"root"` первой, далее по алфавиту;
- файлы внутри каждой группы сортируются по `as_posix()`.

### `subproject_root(project_root, subproject)`

```text
subproject_root(project_root: Path, subproject: str) -> Path
```

Возвращает абсолютный путь корня подпроекта по ключу:

- для `"root"` возвращает `project_root`;
- иначе возвращает `project_root / subproject`.

Проверка существования ключа не выполняется.

## Внутренние помощники

- `_matches_glob(name, pattern)` — сопоставление имени файла glob-паттерну через `fnmatch`.
- `_is_excluded(rel_path, user_excludes)` — проверка исключения по относительному пути: директории из `DEFAULT_EXCLUDE_DIRS`/`user_excludes` и имя файла по default/user-паттернам.
- `_normalize_extensions(extensions)` — нормализация расширений: нижний регистр, ведущая точка, пустые значения отбрасываются.
- `_run_git(project_root, args, timeout=30)` — запуск git-команды через `subprocess.run` с `capture_output=True`, `text=True`, таймаутом 30 секунд. Ошибки логируются как warning; при ошибке возвращается `None`.
- `_get_git_commits(project_root, limit)` — получение последних `limit` коммитов без merge через `git log --no-merges -<limit> --pretty=format:%H|%s|%b`. Парсинг выполняется по строкам, начинающимся с 40-символьного SHA.
- `_get_tracked_files(project_root)` — получение относительных путей отслеживаемых файлов через `git ls-files`.
- `_collect_git_data(project_root, use_git, changelog_limit)` — сбор git-данных, если git разрешён и в `project_root` есть `.git`.
- `_iter_filesystem(scan_root, project_root, extensions, user_excludes)` — рекурсивный обход файловой системы с фильтрами.
- `_iter_tracked(git_data, project_root, scan_prefix, extensions, user_excludes)` — обход отслеживаемых файлов с учётом `src_dir`-префикса, расширений и исключений; файлы, отсутствующие на диске, пропускаются.
- `_dir_is_excluded(name, user_excludes)` — проверка исключения директории при поиске корней подпроектов.
- `_root_index(project_root, roots)` — отображение ключ подпроекта -> абсолютный путь корня.
- `_subproject_for_file(path, project_root, index)` — определение ключа ближайшего подпроекта для файла.
- `_count_untracked(...)` — информативный подсчёт файлов на диске, которые не отслеживаются git. Ошибки не критичны и логируются как warning.

## Правила сканирования и git-данных

- Git-данные собираются только если `use_git=True` и в `project_root` существует `.git`.
- Если `.git` не найден, модуль работает без git-данных и выполняет обход файловой системы.
- Если `git ls-files` вернул пустой список, модуль логирует warning и возвращает `GitData(has_git=False)`, после чего используется файловый обход.
- Ошибки git-команд логируются как warning; сканирование продолжается без git-данных.
- При активном git используются только отслеживаемые файлы, прошедшие фильтры по расширениям и исключениям.
- Отслеживаемые файлы, отсутствующие на диске, пропускаются.
- Для файловой системы обход выполняется от `scan_root` через `rglob("*")`; проверяются только файлы с подходящим последним расширением.
- Исключения директорий проверяются по всем частям относительного пути, кроме имени файла.
- Имя файла проверяется по `DEFAULT_EXCLUDE_FILE_PATTERNS` и `user_excludes` через `fnmatch`.
- При поиске подпроектов скрытые директории и символические ссылки не просматриваются.

## Использование другими модулями проекта

В изолированном файле нет импортов других модулей проекта, поэтому конкретные потребители не видны. Ожидаемые точки интеграции:

- вызов `scan()` или `scan_grouped()` из оркестратора пайплайна для получения файлов и git-данных;
- использование `find_subproject_roots()`, `group_by_subproject()` и `subproject_root()` для обработки монорепозиториев;
- использование `ROOT_SUBPROJECT` как ключа корневой группы;
- использование `GitData` и `GitCommit` для передачи данных о коммитах и отслеживаемых файлах в соседние этапы обработки.

## Ограничения и заметки

- Проверка наличия git-репозитория выполняется только по `project_root / ".git"`; родительские директории не проверяются.
- `scan()` поднимает `ValueError`, если `project_root` не директория или `src_dir` не найден/не является директорией.
- При пустом списке расширений сканирование сразу возвращает пустой результат и `GitData(has_git=False)`.
- `user_excludes` используется и как список имён директорий, и как набор glob-паттернов для имён файлов.
- `find_subproject_roots()` не просматривает скрытые директории и символические ссылки.
- `_count_untracked()` предназначен только для информационного логирования и не влияет на результат сканирования.
- Существующая документация в предоставленном запросе отсутствует, поэтому сохранённых разделов нет.
