# Модуль сканирования проекта

## Назначение

Модуль собирает список файлов проекта и git-метаданные для последующей обработки: сканирования кода, генерации документации/CHANGELOG и группировки файлов по подпроектам монорепозитория.

Основные возможности:
- сканирование только отслеживаемых git-файлов через `git ls-files`;
- резервный рекурсивный обход файловой системы, если git недоступен или отключён;
- фильтрация по расширениям и исключениям;
- сбор последних git-коммитов;
- определение корней подпроектов по маркерам;
- группировка файлов по подпроектам.

## Публичный API

### `scan(project_root, src_dir, extensions, user_excludes, use_git, changelog_limit)`

Сканирует проект и возвращает кортеж `(files, git_data)`.

Параметры:
- `project_root: Path` — корень целевого проекта. Должен быть директорией.
- `src_dir: str | None` — относительная подпапка с кодом. Если задана, должна существовать и быть директорией.
- `extensions: list[str]` — расширения файлов, например `['.py', '.ts']`. Нормализуются к нижнему регистру и виду с точкой.
- `user_excludes: list[str]` — пользовательские исключения: имена папок и glob-паттерны файлов.
- `use_git: bool` — если `False`, git-данные не собираются, используется обход файловой системы.
- `changelog_limit: int` — сколько последних коммитов запрашивать для CHANGELOG.

Возвращает:
- `list[Path]` — абсолютные пути файлов, отсортированные по строковому пути;
- `GitData` — собранные git-данные.

Если `extensions` пуст, возвращается `([], GitData(has_git=False))`.

### `scan_grouped(project_root, src_dir, extensions, user_excludes, use_git, changelog_limit)`

Работает как `scan()`, но возвращает `(grouped_files, git_data)`, где `grouped_files` — словарь `dict[str, list[Path]]`.

Ключи групп:
- `"root"` — корневой проект и файлы вне известных подпроектов;
- относительный POSIX-путь корня подпроекта от `project_root`.

Порядок групп: сначала `"root"`, затем по алфавиту. Файлы внутри группы отсортированы по пути.

### `find_subproject_roots(project_root, user_excludes)`

Ищет каталоги-корни подпроектов по маркерам из `SUBPROJECT_MARKERS`.

Параметры:
- `project_root: Path` — корень проекта;
- `user_excludes: list[str]` — исключения для каталогов.

Возвращает отсортированный список абсолютных `Path`. Сам `project_root` тоже может быть корнем подпроекта. Скрытые каталоги, символические ссылки и исключённые каталоги при обходе пропускаются.

### `group_by_subproject(files, project_root, user_excludes)`

Группирует переданные файлы по ближайшему самому глубокому корню подпроекта-предку.

Возвращает `dict[str, list[Path]]` с ключами `"root"` или относительными POSIX-путями корней подпроектов.

### `subproject_root(project_root, subproject)`

Возвращает абсолютный путь корня подпроекта по ключу. Для `"root"` возвращает сам `project_root`. Существование пути не проверяется.

### `ROOT_SUBPROJECT`

Константа `"root"` — ключ корневого проекта и файлов вне известных подпроектов.

## Классы

### `GitCommit`

Frozen dataclass с полями:
- `sha: str` — SHA коммита;
- `subject: str` — тема коммита;
- `body: str` — тело коммита, возможно многострочное.

### `GitData`

Dataclass с полями:
- `has_git: bool` — удалось ли использовать git-данные;
- `commits: list[GitCommit]` — последние коммиты без merge-коммитов;
- `tracked_files: set[str]` — относительные пути отслеживаемых файлов из `git ls-files`.

## Константы

- `DEFAULT_EXCLUDE_DIRS` — исключаемые по умолчанию каталоги: `.git`, `.doxdix`, `node_modules`, `__pycache__`, `venv`, `.venv`, `env`, `dist`, `build`, `tests`, `test`, `.mypy_cache`, `.pytest_cache`, `.ruff_cache`, `target`.
- `DEFAULT_EXCLUDE_FILE_PATTERNS` — исключаемые по умолчанию файлы: `test_*`, `*_test.*`, `*.min.*`, `*.spec.*`, `conftest.py`.
- `SUBPROJECT_MARKERS` — маркеры корня подпроекта: `pyproject.toml`, `package.json`, `Cargo.toml`, `go.mod`.
- `ROOT_SUBPROJECT` — ключ `"root"`.
- `dv_file_version` — версия файла: `"261028.03"`.

## Логика работы

1. `project_root` разрешается через `resolve()`. Если это не директория, выбрасывается `ValueError`.
2. Если задан `src_dir`, вычисляется `scan_root`. Для git-режима формируется префикс `src_dir.strip("/") + "/"`.
3. Расширения нормализуются. Пустой список расширений означает отсутствие результатов.
4. Пытается собрать git-данные:
   - если `use_git=False`, git отключён;
   - если нет `.git`, работа идёт без git;
   - если `git ls-files` вернул пустой набор, используется файловый обход;
   - если git-команды падают, пишутся warning-логи, сканирование продолжается без git.
5. При доступном git сканируются только отслеживаемые файлы, подходящие по префиксу, расширениям и исключениям. Файлы из индекса, отсутствующие на диске, пропускаются.
6. Без git выполняется рекурсивный обход файловой системы от `scan_root`.
7. Для информационного лога дополнительно считается количество неотслеживаемых файлов на диске.
8. Результат сортируется. При группировке вызываются `find_subproject_roots()` и `group_by_subproject()`.

Исключения проверяются по относительному пути от `project_root`:
- любая родительская часть пути входит в `DEFAULT_EXCLUDE_DIRS` или `user_excludes`;
- имя файла совпадает с `DEFAULT_EXCLUDE_FILE_PATTERNS` или `user_excludes`.

Для glob-сопоставления используется `fnmatch`. На POSIX сопоставление регистрозависимо.

## Git-детали

- Команды git выполняются через `subprocess.run` с `capture_output=True`, `text=True`, таймаутом 30 секунд.
- Коммиты берутся командой `git log --no-merges -<limit> --pretty=format:%H|%s|%b`.
- Если `changelog_limit <= 0`, коммиты не запрашиваются.
- Отслеживаемые файлы берутся командой `git ls-files`.
- Ошибки git логируются как warning и не прерывают сканирование.
- Если `git ls-files` пуст, `GitData.has_git` устанавливается в `False`, и сканирование переходит на файловый обход.

## Зависимости

Модуль использует только стандартную библиотеку:
- `logging` — логирование;
- `subprocess` — вызовы git;
- `dataclasses` — `GitCommit`, `GitData`;
- `pathlib` — работа с путями;
- локально импортируемые `fnmatch` и `re` — сопоставление имён и парсинг вывода git.

Импортов из других модулей проекта нет. Внешняя зависимость — исполняемый файл `git` в `PATH`; при его отсутствии модуль продолжает работу без git-данных.

## Использование другими модулями

В предоставленном коде нет импортов этого модуля другими модулями проекта, поэтому конкретные вызывающие модули не видны.

Внутри модуля видно, что:
- `scan_grouped()` вызывает `scan()` и `group_by_subproject()`;
- `group_by_subproject()` использует `find_subproject_roots()`, `_root_index()` и `_subproject_for_file()`;
- `scan()` использует `_collect_git_data()`, `_iter_tracked()` или `_iter_filesystem()`, а также `_count_untracked()`.

Модуль предназначен для использования через публичный API `scan()` / `scan_grouped()` и функции работы с подпроектами.

## Ограничения и примечания

- `project_root` должен быть существующей директорией.
- `src_dir` ожидается относительным путём; если он задан, должен существовать.
- При пустом списке расширений git-данные не собираются, возвращается пустой результат.
- При отсутствии git, ошибке git или пустом `git ls-files` используется обход файловой системы.
- Если git доступен и `tracked_files` непуст, но коммиты получить не удалось, `has_git` остаётся `True`, а `commits` может быть пустым.
- Пути в результате `scan()` абсолютные.
- Ключи подпроектов и сортировка используют POSIX-представление путей.
- `find_subproject_roots()` не заходит в скрытые каталоги, символические ссылки и исключённые каталоги.
- `subproject_root()` не проверяет существование возвращаемого пути.
