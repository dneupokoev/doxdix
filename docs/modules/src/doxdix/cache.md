## Назначение

Модуль реализует кэш SHA-256-хэшей исходного кода в файле `<project>/.doxdix/cache.json`. Он нужен, чтобы при повторных запусках не отправлять в LLM файлы, код которых не изменился с прошлого запуска, и тем самым экономить токены и время.

Формат кэша:

```json
{"<подпроект>/<относительный/путь.py>": "<sha256 в hex>"}
```

Ключ включает подпроект, поэтому одинаковые относительные пути из разных подпроектов монорепозитория не перетирают друг друга. Для корневого проекта используется префикс `root/`. В режиме `--no-monorepo` ключом служит просто путь от корня проекта.

При `RunConfig.force` / флаге `--force` кэш игнорируется.

## Публичный API

- `CACHE_DIR = ".doxdix"` — имя каталога кэша.
- `CACHE_FILENAME = "cache.json"` — имя файла кэша.
- `cache_file_path(project_root: Path) -> Path` — возвращает путь `<project>/.doxdix/cache.json`.
- `file_sha256(code_path: Path) -> str | None` — считает SHA-256 содержимого файла и возвращает hex-строку. Читает файл порциями по 1 МиБ. При `OSError` логирует предупреждение и возвращает `None`.
- `Cache` — класс для загрузки, изменения и сохранения кэша.

### `Cache`

`Cache(project_root: Path, data: dict[str, str] | None = None)`  
Создаёт объект кэша для указанного корня проекта. Внутри хранит путь к файлу кэша и копию переданных данных.

Методы:

- `Cache.load(project_root: Path) -> Cache` — читает `cache.json`. Если файл отсутствует, повреждён, не читается или содержит не JSON-объект, возвращает пустой кэш и при необходимости пишет предупреждение в лог.
- `get(rel_key: str) -> str | None` — возвращает сохранённый хэш по относительному ключу или `None`.
- `set(rel_key: str, sha: str) -> None` — запоминает хэш файла. Помечает кэш как изменённый только при фактическом изменении значения.
- `is_unchanged(rel_key: str, sha: str, md_path: Path) -> bool` — возвращает `True`, если хэш совпадает с кэшем и итоговый `.md`-файл уже существует.
- `save() -> bool` — записывает кэш, если были изменения. Создаёт родительский каталог при необходимости. Возвращает `True`, если запись не требовалась или прошла успешно, и `False` при `OSError`.

## Зависимости

Импортируются только стандартные модули:

- `hashlib` — расчёт SHA-256.
- `json` — чтение и запись `cache.json`.
- `logging` — диагностические сообщения.
- `pathlib.Path` — работа с путями.
- `__future__.annotations` — отложенная аннотация типов.

Внутренних импортов из других модулей проекта нет.

## Использование в проекте

Судя по docstring модуля:

- `orchestrator._step_modules` использует ключи вида `<подпроект>/<относительный/путь.py>`; для корневого проекта применяется префикс `root/`.
- `cli.py` при `RunConfig.force` / флаге `--force` игнорирует кэш.
- Механизм кэша позволяет пропускать неизменённые файлы при подготовке данных для LLM.
- `is_unchanged` дополнительно требует наличия итогового `.md`-файла, то есть одного совпадения хэша недостаточно.

## Ограничения и поведение

- Отсутствующий или битый файл кэша не является фатальной ошибкой: кэш считается пустым.
- `save()` не перезаписывает файл, если изменений не было.
- Содержимое итогового `.md`-файла не проверяется; для `is_unchanged` важно только его существование.
- При ошибке чтения исходного файла `file_sha256` возвращает `None` и пишет предупреждение в лог.
- Модуль не содержит явной синхронизации для конкурентной записи `cache.json`.
