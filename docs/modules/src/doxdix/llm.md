# HTTP-клиент LLM: Ollama и OpenAI-совместимый API

## Назначение

Модуль предоставляет единый HTTP-клиент для работы с LLM через два режима:

- **Ollama**: `/api/chat`, `/api/tags`
- **OpenAI-совместимый API**: `/chat/completions`, `/models`

Режим определяется автоматически по `base_url`:

- если URL оканчивается на `/v1` или содержит `/v1/` — используется OpenAI-совместимый режим;
- иначе — Ollama-режим.

Публичный API модуля: `LLMError`, `chat()`, `check_model()`.

Версия файла: `261028.12`.

## Публичный API

### `LLMError`

Исключение LLM-клиента.

Аргументы:

- `message: str` — текст ошибки;
- `status: int | None = None` — HTTP-код, если он есть;
- `body: str | None = None` — тело ответа, обычно обрезанное до 1000 символов.

Атрибуты исключения: `message`, `status`, `body`.

### `chat(base_url, model, prompt, num_ctx, timeout, api_key="dummy") -> str`

Отправляет промпт в LLM и возвращает `content.strip()`.

Аргументы:

- `base_url: str` — базовый URL LLM-сервера;
- `model: str` — имя модели;
- `prompt: str` — пользовательский промпт;
- `num_ctx: int` — размер контекста для Ollama;
- `timeout: int` — таймаут HTTP-запроса в секундах;
- `api_key: str = "dummy"` — ключ для OpenAI-совместимого режима.

Поведение:

- В OpenAI-режиме вызывается `_chat_openai()`; `num_ctx` игнорируется.
- В Ollama-режиме вызывается `_chat_ollama()`; `num_ctx` передаётся в `options.num_ctx`.
- В Ollama-режиме, если `len(prompt) // 4 > num_ctx`, пишется предупреждение в лог, но запрос не блокируется.
- При HTTP-статусе не `200`, не-JSON ответе, отсутствии `content` или пустом `content` выбрасывается `LLMError`.
- При таймауте или ошибке `requests` выбрасывается `LLMError`.

### `check_model(base_url, model, timeout=10, api_key="dummy") -> list[str]`

Проверяет доступность LLM-сервера и возвращает список имён моделей.

Аргументы:

- `base_url: str` — базовый URL LLM-сервера;
- `model: str` — имя проверяемой модели; в текущей реализации аргумент принимается, но внутри `check_model()` не используется;
- `timeout: int = 10` — таймаут HTTP-запроса;
- `api_key: str = "dummy"` — ключ для OpenAI-совместимого режима.

Поведение:

- В OpenAI-режиме вызывается `_check_openai()`.
- В Ollama-режиме вызывается `_check_ollama()`.
- Для OpenAI-режима имена моделей берутся из `data[].id`.
- Для Ollama-режима имена моделей берутся из `models[].name`.
- Если сервер недоступен, возвращает не `200`, отдаёт не-JSON или возникает сетевая ошибка/таймаут, выбрасывается `LLMError`.
- В OpenAI-режиме HTTP `404` на `/models` не считается фатальной ошибкой: пишется предупреждение и возвращается `[]`. Это означает, что проверка имени модели пропускается.
- В Ollama-режиме пустой `/api/tags` считается ошибкой `LLMError`, так как моделей нет и запрошенной модели точно нет.

## Режимы и HTTP-эндпоинты

### Ollama-режим

Используется, если `base_url` не похож на OpenAI-совместимый.

Эндпоинты:

- `POST {base}/api/chat`
- `GET {base}/api/tags`

Особенности:

- авторизация не используется;
- `num_ctx` передаётся в `options.num_ctx`;
- имена моделей читаются из `models[].name`;
- пустой список моделей в `/api/tags` вызывает `LLMError`.

### OpenAI-совместимый режим

Используется, если `base_url` оканчивается на `/v1` или содержит `/v1/`.

Эндпоинты:

- `POST {base}/chat/completions`
- `GET {base}/models`

Особенности:

- если `api_key` не пустой, добавляется заголовок `Authorization: Bearer <api_key>`;
- если `api_key` пустой, заголовок авторизации не добавляется;
- `num_ctx` игнорируется;
- имена моделей читаются из `data[].id`;
- HTTP `404` на `/models` возвращает `[]` с предупреждением в лог.

## Внутренние функции

- `_is_openai_mode(base_url)` — определяет OpenAI-совместимый режим по URL.
- `_ollama_chat_url(base_url)` — формирует URL `/api/chat`.
- `_ollama_tags_url(base_url)` — формирует URL `/api/tags`.
- `_openai_chat_url(base_url)` — формирует URL `/chat/completions`.
- `_openai_models_url(base_url)` — формирует URL `/models`.
- `_auth_headers(api_key)` — формирует заголовок `Authorization` для OpenAI-режима.
- `_chat_ollama(...)` — выполняет запрос к Ollama `/api/chat`.
- `_check_ollama(...)` — выполняет запрос к Ollama `/api/tags`.
- `_chat_openai(...)` — выполняет запрос к OpenAI-совместимому `/chat/completions`.
- `_check_openai(...)` — выполняет запрос к OpenAI-совместимому `/models`.

## Обработка ошибок

`LLMError` выбрасывается при:

- HTTP-статусе, отличном от `200`;
- таймауте запроса;
- сетевой ошибке `requests.RequestException`;
- не-JSON ответе;
- отсутствии ожидаемого поля с `content`;
- пустом или нестроковом `content`;
- пустом списке моделей Ollama в `/api/tags`.

Тело ответа в `LLMError.body` обычно обрезается до 1000 символов.

## Зависимости

Импорты:

- `from __future__ import annotations` — отложенная аннотация типов;
- `logging` — логирование предупреждений;
- `requests` — HTTP-запросы к LLM-серверам.

Модуль не импортирует другие модули проекта.

## Использование в проекте

Модуль предоставляет публичные функции `chat()` и `check_model()`, предназначенные для использования другими модулями проекта.

Согласно docstring, наличие запрошенной модели проверяет вызывающая сторона, например `cli.py`, чтобы при необходимости показать пользователю список доступных моделей. Точные импорты и вызовы из других модулей в изолированном файле не видны.

Типичный сценарий:

1. Другой модуль вызывает `check_model(base_url, model, ...)` для проверки доступности LLM-сервера и получения списка моделей.
2. Вызывающая сторона сама проверяет, есть ли нужная модель в возвращённом списке.
3. Для отправки промпта другой модуль вызывает `chat(base_url, model, prompt, num_ctx, timeout, api_key)`.
4. При ошибке вызывающая сторона обрабатывает `LLMError`, используя поля `message`, `status`, `body`.
