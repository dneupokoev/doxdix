# prompts.py

## Назначение
Модуль содержит русскоязычные шаблоны промптов для LLM, используемые при создании и обновлении Markdown-документации проекта. Промпты требуют от модели вернуть полный текст `.md` — не diff, не фрагмент и без обрамляющих троек обратных кавычек. Версия файла: `261028.17`.

## Публичный API
- `SUMMARY_PROMPT` — шаблон для создания или дополнения `docs/SUMMARY.md`.
- `SUMMARY_FINAL_PROMPT` — шаблон для финального дополнения `docs/SUMMARY.md` ссылками на созданные/обновлённые файлы.
- `README_PROMPT` — шаблон для обновления `README.md`.
- `MODULE_PROMPT` — шаблон для изолированного анализа отдельного файла кода и обновления его документации.
- `CHANGELOG_LLM_PROMPT` — шаблон для переписывания сгруппированных git-изменений в user-facing формулировки для `CHANGELOG.md`.
- `render(template: str, **kwargs: object) -> str` — подстановка значений в шаблон.

Классов в модуле нет; публичный API состоит из строковых констант и одной функции.

## Шаблоны промптов

### `SUMMARY_PROMPT`
Плейсхолдеры: `{project_context}`, `{modules_content}`, `{existing_content}`.

Создаёт или дополняет `docs/SUMMARY.md` как оглавление и краткий обзор проекта. Опирается на README и содержимое уже созданных модульных `.md`-файлов, сохраняет существующие разделы и ссылки, формирует ссылки относительно `docs/`, не добавляет раздел про лицензию и не дублирует README. Требует не выдумывать назначение проекта, если его нет в README.

### `SUMMARY_FINAL_PROMPT`
Плейсхолдеры: `{modules_content}`, `{existing_content}`.

Добавляет в `docs/SUMMARY.md` ссылки на созданные/обновлённые файлы документации и уточняет назначение модулей по их содержимому. Сохраняет существующие разделы и ссылки, не добавляет разделы «Установка», «Использование», «Быстрый старт» и лицензию.

### `README_PROMPT`
Плейсхолдеры: `{project_context}`, `{file_list}`, `{recent_commits}`, `{existing_content}`.

Обновляет `README.md`: назначение, установка, использование, структура. Сохраняет вручную написанные разделы и конкретные примеры запуска с флагами, не выдумывает команды и флаги. Не добавляет раздел про лицензию; если он уже есть в существующем README — оставляет без изменений.

### `MODULE_PROMPT`
Плейсхолдеры: `{code_content}`, `{existing_content}`.

Изолированно анализирует файл кода и обновляет документацию модуля: главное назначение, основные функции/классы и их аргументы, зависимости по импортам, использование модуля другими частями проекта, если это видно из импортов и вызовов. Сохраняет непротиворечивые разделы существующей документации.

### `CHANGELOG_LLM_PROMPT`
Плейсхолдер: `{grouped_commits}`.

Переписывает сгруппированные по типам изменения из git-коммитов в user-facing формулировки для `CHANGELOG.md`. Сохраняет факты и группировку, возвращает только содержимое секции `[Unreleased]` в Markdown.

## Функция `render`
`render(template: str, **kwargs: object) -> str` подставляет именованные аргументы в шаблон через `str.format`. Подставляемые значения не форматируются повторно, поэтому фигурные скобки внутри кода или README не интерпретируются как поля формата. Ограничение: в самом шаблоне не должно быть незаэкранированных фигурных скобок, кроме плейсхолдеров; в текущих шаблонах таких скобок нет.

## Зависимости
- `from __future__ import annotations` — для отложенных аннотаций типов.
- Внешних библиотек и импортов других модулей проекта нет.

## Использование другими модулями
В изолированном файле не видно, какие модули проекта импортируют этот модуль. Публичный API предназначен для использования в коде генерации документации: шаблоны можно передавать в `render` вместе с контекстом проекта, содержимым файлов и существующей документацией.

## Примечания
- Все промпты на русском языке.
- Промпты требуют вернуть только текст `.md`, без diff, фрагментов и обрамляющих троек обратных кавычек.
- Шаблоны соответствуют п. 7.1–7.4 ТЗ с усилениями v12.
- `dv_file_version` содержит версию файла: `261028.17`.
