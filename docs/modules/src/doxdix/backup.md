# Модуль бэкапа документации

## Назначение

Модуль отвечает за резервное копирование, восстановление и ротацию документации проекта.

Бэкап включает:
- `README.md`;
- `CHANGELOG.md`;
- всё содержимое каталога `docs/`.

Каждый бэкап сохраняется в отдельный каталог:
`<backup_dir>/<ISO-timestamp>/`

В каталоге бэкапа создаётся `manifest.json` формата:

`{"timestamp": ..., "files": [{"path": ..., "sha256": ...}]}`

Модуль не прерывает конвейер при ошибках: большинство ошибок логируется, а публичные функции возвращают `None`.

## Публичный API

### `create_backup(project_root: Path, backup_dir: Path, keep: int) -> Path | None`

Создаёт бэкап документации проекта.

Аргументы:
- `project_root` — корень проекта, из которого собираются файлы;
- `backup_dir` — каталог для хранения бэкапов;
- `keep` — количество последних бэкапов, которое нужно оставить после ротации.

Поведение:
- собирает `README.md`, `CHANGELOG.md` и файлы из `docs/`, если они существуют;
- если копировать нечего, пишет info в лог и возвращает `None`;
- создаёт каталог бэкапа с уникальным timestamp;
- при коллизии timestamp добавляет суффиксы `-1`, `-2`, ...;
- копирует файлы с сохранением метаданных через `shutil.copy2`;
- вычисляет SHA-256 для каждого скопированного файла и записывает manifest;
- выполняет ротацию, оставляя `keep` последних бэкапов;
- возвращает `Path` созданного бэкапа или `None` при ошибке.

Особенность: при `keep <= 0` ротация не выполняется.

### `restore_backup(project_root: Path, backup_dir: Path, timestamp: str) -> int | None`

Восстанавливает файлы из бэкапа по timestamp.

Аргументы:
- `project_root` — корень проекта, куда восстанавливаются файлы;
- `backup_dir` — каталог с бэкапами;
- `timestamp` — имя каталога бэкапа.

Поведение:
- проверяет наличие каталога бэкапа и `manifest.json`;
- читает manifest;
- копирует файлы из бэкапа обратно в проект;
- отсутствующие в бэкапе файлы проекта не удаляются;
- если файл из manifest отсутствует в бэкапе, пишет warning и пропускает его;
- возвращает число восстановленных файлов или `None`, если бэкап не найден или manifest повреждён.

### `list_backups(backup_dir: Path) -> list[str]`

Возвращает список timestamp-каталогов существующих бэкапов.

Поведение:
- если каталога нет, возвращает пустой список;
- учитывает только каталоги;
- исключает имена, начинающиеся с `.`;
- сортирует имена в обратном лексикографическом порядке, то есть «свежие сверху».

## Внутренние функции

- `_iso_timestamp()` — формирует текущий timestamp в формате `YYYY-MM-DDTHH-MM-SS`.
- `_sha256(path)` — вычисляет SHA-256 файла потоково, блоками по 64 KiB.
- `_unique_backup_dir(backup_dir)` — подбирает свободное имя каталога бэкапа с учётом суффиксов при коллизии.
- `_rotate(backup_dir, keep)` — удаляет старые бэкапы, оставляя `keep` последних. Ошибки удаления логируются.
- `_collect_backup_targets(project_root)` — собирает относительные пути файлов для бэкапа.

## Зависимости

Используются только стандартные библиотеки Python:
- `hashlib`;
- `json`;
- `logging`;
- `shutil`;
- `datetime`;
- `pathlib`;
- `__future__.annotations`.

Внутренних зависимостей от других модулей проекта в файле нет.

## Использование другими модулями

В предоставленном файле нет импортов данного модуля другими модулями, поэтому конкретные потребители не видны. Модуль предназначен для использования через публичные функции:

- `create_backup(...)` — создание резервной копии;
- `restore_backup(...)` — восстановление из выбранного бэкапа;
- `list_backups(...)` — получение списка доступных timestamp для выбора бэкапа.

Типовой сценарий: получить список бэкапов через `list_backups`, затем передать выбранный timestamp в `restore_backup`.

## Ограничения и заметки

- Восстановление не удаляет файлы, которых нет в бэкапе.
- При восстановлении не выполняется проверка SHA-256 из manifest.
- `list_backups` возвращает все не скрытые каталоги в `backup_dir`, не проверяя, что они являются корректными бэкапами.
- Пути из manifest при восстановлении используются без отдельной валидации на выход за пределы `project_root`.
- При ошибке копирования отдельного файла создание бэкапа продолжается; в manifest попадают только успешно скопированные файлы.
- Если запись `manifest.json` не удалась, `create_backup` возвращает `None`, но уже созданный каталог бэкапа не удаляется автоматически.
